# 动作慢放内核与图形播放器

对自制运动视频做技术动作讲解用的慢放：**保持音高的时间伸缩** + **按共同媒体时钟取帧** +
**可圈定区间循环**。播放速度、音频产出速率与输出时钟分开处理；音频不使用“拉长定时器”
的方式，也不会通过静音来回避同步问题。

---

## 图形入口（主入口）

```bash
npm install
npm run dev
```

浏览器打开 <http://127.0.0.1:5173/>（会自动进入 `/src/player/index.html`）。
页面需要安全上下文（localhost 满足），因为 WebCodecs 与 AudioWorklet 依赖它。

播放器功能：

- **播放 / 暂停 / 逐帧**（空格、←、→）
- **速度滑杆**（0.10×–1.50×，步进 0.05）与 0.25× / 0.5× / 0.75× / 1.00× / 1.25× 预设；
  双击右上角速率数字可输入范围外数值，用于验证“超限拒绝”
- **时间轴拖拽圈定区间**，拖动两端手柄微调，也可直接编辑“入/出”秒数
- **循环区间**开关
- **结果区**：实际采用速率、请求速率、速率档位、循环动作（第几遍）、循环区间、
  播放位置、当前帧 / 总帧、位置来源
- **时钟偏差区**：固定偏移、漂移速率（ppm）、记录的音频延迟（设备 / 输出 / 算法）、
  音频缓冲、欠载次数、视频已解码量
- **音频示波器**：取自 `AudioContext` 实际输出的 `AnalyserNode`，变速时仍可见波形

结果区的所有数值来自 `SlowmoEngine.stats()` 的实时运行状态，按钮直接调用引擎
（`play()`、`pause()`、`setRate()`、`setRegion()`、`seek()`），没有用固定数据冒充。

演示片段由开发服务器从 `tests/fixtures` 读取并通过 `/api/demos` 提供；
也可载入本地自制 MP4（H.264 + AAC）。

## 支持的速率范围

| 范围 | 行为 |
|---|---|
| 0.10× – 1.50× | 可播放。超出 `0.25×–1.25×` 时标记为“音质降级”并给出提示 |
| 0.25× – 1.25× | 音质保证区（WSOLA 重复/压缩段较小） |
| 1.00× | 原速直通 |
| < 0.10× 或 > 1.50× | **拒绝**，保持上一速率，界面显示拒绝原因 |

“音质降级”是如实标注：低倍率重复段增大、高倍率压缩段增大，**不宣称任意倍率都无失真**。
策略定义在 `src/kernel/rates.js`（`RATE_POLICY`），界面文案与拒绝逻辑共用同一份定义。

## 处理链

```
MP4 ──mp4box 解封装（edts 修正、AAC priming）──┬─ 视频样本 ─→ WebCodecs VideoDecoder ─→ 解码帧队列
                                              └─ 音频样本 ─→ WebCodecs AudioDecoder ─→ PCM
                                                                                  │
                                                    WSOLA 时间伸缩（音高不变） ──────┘
                                                                                  │
                                            AudioWorklet 环形缓冲（原始输出速率）
                                                                                  │
                                                                        AudioContext 硬件时钟
                                                                                  │
                            共享媒体时钟：out 时间 × 速率斜率 → program（虚拟）时间
                                                                                  │
                                         ┌────────────────────────────────────────┴──────┐
                                   取帧：frameAt(program)                      界面 / 统计
```

要点：

- **速率不改变定时器间隔。** 时钟按真实时间推进，速率只是“输出秒 → 节目秒”的斜率；
  音频始终以设备采样率实时产出，变速来自 WSOLA，而不是让音频按原速继续跑。
- **缓冲区协调。** `_fillRing()` 按 `_queueAhead()`（已入队 − 设备已消费）维持约 0.16 s
  的环形缓冲；变速时按新速率重新计算每次可产出的上限，并在区间边界硬切。
- **算法延迟进入同步。** `_measureLatency()` 记录设备 `baseLatency`、`outputLatency` 与
  WSOLA 前瞻（`lookaheadOutputSamples / sampleRate`）。播放位置取音频渲染器实际消费的
  采样数映射回节目时间，因此固定的算法/设备延迟表现为**固定偏移**，不计为失步；
  漂移速率由偏移对时间的斜率估计（2 s 窗口，见 `_trackDrift`）。
- **循环切点。** 圈定区间在虚拟时间轴上表现为显式切点（`_addCut`），虚拟位置跨遍连续，
  因此循环不会被误判成时钟漂移。
- **区间末尾。** WSOLA 需要一帧 + 搜索窗的前瞻；接近媒体末尾时以静音补齐
  （`endOfInput()`），否则区间结束于节目末尾时会停在最后约 36 ms。
- **视频。** `VideoSource.frameAt(programSeconds)` 按 pts 二分查找覆盖当前时钟位置的帧，
  与显示刷新率无关；循环回绕时在新一遍开始处重新起播解码器，旧帧保持显示直到新帧就绪。

## 测试

```bash
npm test            # 单元测试 + 浏览器集成测试
npm run test:unit   # WSOLA、速率策略、时钟/循环时间轴（Node）
npm run test:browser# 真实浏览器中的内核与播放器（Playwright + Chromium）
```

浏览器测试需要 Chromium。若本机未安装，仓库内的 `.cache/ms-playwright` 会被自动使用
（测试夹具与库已在 `.cache` 下）；否则执行 `npx playwright install chromium`。

覆盖内容：

- **WSOLA**：时长随倍率变化（误差 < 20 ms）、音高在 1% 内保持、拼接处无跳变、
  立体声相位一致、流式渲染在 `endOfInput()` 后达到目标时长、饥饿如实上报。
- **速率策略**：边界值、超限拒绝、降级标注、非数字输入。
- **真实处理链**（0.5×）：实际采用速率、位置前进、零欠载、输出非静音、
  持续音仍约 440 Hz、算法延迟已记录。
- **取帧**：解码帧覆盖共享时钟位置（误差 ≤ 1 帧）。
- **循环**：多遍循环、位置不越界、跨切点偏差有界。
- **变速**：播放中改速后偏差回到固定偏移量级，不产生永久失步。
- **脉冲**：0.5× 下脉冲间距约 1 s，位置正确。
- **播放器**：按钮驱动真实引擎、结果区数值随时间变化、超限拒绝、
  时间轴拖拽圈定区间、入/出输入、画布显示真实解码帧、音频示波器有波形。

测试夹具由 `npm run fixtures` 生成（需 ffmpeg，已作为依赖提供）：

- `numbered-640x360-30fps.mp4`：每帧绘制帧号，用于核对取帧位置；
- `pulses-320x240-25fps.mp4`：每 0.5 s 一个 1 kHz 脉冲，用于核对音画位置。

音频为 440 Hz 持续音 + 已知时刻的脉冲；WAV 由 Node 精确合成，再与视频一起编码，
因此脉冲时刻是测试的基准真值。

## 命令行（辅助）

主入口是上面的图形播放器。命令行只是批处理辅助，它同样走真实的 WSOLA 离线路径：

```bash
node scripts/cli.mjs tests/fixtures/numbered-640x360-30fps.mp4 \
  --rate 0.5 --from 1 --to 3 --out slow.wav
```

输出区间、实际采用速率、输出时长、采样数、音高与电平；`--json` 输出机器可读结果。
超限速率会被拒绝并返回非零退出码。

## 已知限制

- 需要支持 WebCodecs 与 AudioWorklet 的浏览器（当前为 Chromium 系；Safari 的
  WebCodecs 支持仍不完整）。页面必须在安全上下文（HTTPS 或 localhost）下运行。
- 视频编码需为浏览器可解的 H.264/H.265；音频为 AAC。
- WSOLA 在低倍率下会有轻微“重复感”，这是该算法的固有限制，因此 0.25× 以下标注降级。
- 输出钟以 `AudioContext` 为准；不同设备的 `baseLatency`/`outputLatency` 会不同，
  但它们作为固定偏移被记录并排除在漂移之外。
